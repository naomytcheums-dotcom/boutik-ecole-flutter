# Questions — Section V (Onboarding, guide, rôles : 175–181)

1. **175–178 — texte sur photo.** Les maquettes posent le titre et le sous-titre sur la photo d'en-tête (contraire à la règle « pas de texte dans une carte-photo »). Conservé avec un dégradé sombre pour garantir le contraste. À confirmer.
2. **175–178 — enchaînement.** « Passer » ouvre l'accueil (03). Le bouton principal ouvre l'espace du rôle : étudiant → 57, acheteur → 03, entreprise → 88, jury → 167. Les lignes de fonctionnalités ouvrent l'écran correspondant (ex. hackathons → 160, payer en sécurité → 171). Ces cibles sont déduites (pas d'interaction de prototype lisible).
3. **178 — photo du jury.** La maquette n'a qu'un fond dégradé gris foncé, sans photo. Reproduit tel quel.
4. **179 — vidéo et visite.** « Prendre en main Boutik-École » (badge Vidéo) et « Lancer la visite » n'ont pas d'écran cible. La vidéo affiche « Lecture de la vidéo… » et « Lancer la visite » ouvre le tutoriel 01. Faut-il un lecteur vidéo ?
5. **180 — « Créer un rôle ».** Aucun formulaire de création de rôle dans les maquettes. Le bouton affiche un message invitant à définir les permissions dans la matrice (181).
6. **181 — matrice.** Les valeurs « Oui / — / Valide » viennent des données de démonstration. Les vrais droits doivent être appliqués côté serveur (voir BACKEND_PLAN.md, matrice de l'écran 281).
